## Clepso 0.1.0 alpha 1

**Your coding-agent limits, before you hit them.** Clepso is a menu bar app for macOS that shows how much of your
Claude Code and Codex usage limits you have used, when they reset and how fast you are going, from what those agents
report on your own Mac.

This is the first public pre-release. It runs daily on the maintainer's Mac against real Claude Code sessions, but it
has had few other users yet: expect rough edges, and please [report what you find](https://github.com/obileonardo/clepso/issues).

### What it does today

- **In the menu bar:** a pixel mark for your most pressing limit, across Claude Code and Codex. Its shape changes as
  well as its colour when a limit gets close, runs out or goes stale.
- **The panel** (click the mark): your 5-hour and 7-day limits as a percentage, in words, with the reset time and a
  countdown. It also shows how fresh each number is and a labelled *estimate* of when your current pace reaches 100%.
  Below that: the current session's model, context used, cost estimate, cache hits, lines changed and agents.
- **Codex** 5-hour and weekly limits beside Claude Code's (off until you turn it on in Settings).
- **Alerts** at 80%, 95% and 100% of a limit, when a reset is due and when a limit is ready again, with a one-hour
  snooze. **Quiet hours** and **reset reminders** are there too, both off by default.
- **The Dashboard:** Home (what needs you today), Limits charted over each window, Session details with agents per
  task, and Overview and Models (activity calendar, tokens per day, model shares and levels; these read Claude Code's
  statistics file only if you allow it).
- **Settings:** five colour themes with light and dark palettes, Open at login, notifications, the Claude Code and
  Codex connections, export, demo data, a diagnostics log and Delete all.

More is coming in the next release.

### Install

1. Download `Clepso-0.1.0-alpha.1.dmg` below. It needs **macOS 14 or later on a Mac with Apple silicon** (M1 or newer).
   Optionally, check it: `shasum -a 256 -c SHA256SUMS` in the folder holding both files should print `OK`.
2. Open the disk image and drag **Clepso** into **Applications**. Install it there before the first launch: Open at
   login only works from Applications.
3. Open Clepso from Applications. It is signed with a Developer ID and notarised by Apple, so macOS opens it after the
   usual "downloaded from the internet" question.
4. Follow the welcome window. To read Claude Code's limits, Clepso asks to connect to Claude Code. It shows you the one
   setting it changes, `statusLine.command` in `~/.claude/settings.json`, and keeps a byte-exact backup first.
5. On the last step, switch on **Open at login** if you want Clepso to start with your Mac (off unless you choose it;
   you can change it later in Settings). Then eject the disk image.

Limits appear after Claude Code's next reply in a terminal: Claude Code sends them each time it runs.

### Private by design

- **No network in this build.** This build has no accounts, so Clepso never signs in, uploads or checks for updates.
  Everything stays on your Mac.
- **Allowlist, not blocklist.** The helper that Claude Code runs copies only named fields (limits, model, token and
  cache counts, durations, line counts, the cost estimate). It never forwards your prompts, replies, file paths,
  transcript or project names, and it cannot reach the network.
- **Reversible.** Connecting changes one key in your Claude Code settings after a backup; removing restores the
  original bytes. If you already had a status line, it keeps working.
- **Yours to take or delete.** Settings › Your data has Export (a JSON file of everything stored) and Delete.

The full design is in [`docs/PRIVACY_AND_SECURITY.md`](https://github.com/obileonardo/clepso/blob/main/docs/PRIVACY_AND_SECURITY.md).

### What "alpha" means here

- **No automatic updates.** Clepso does not check for new versions (that would be network traffic). Use GitHub's
  **Watch › Custom › Releases** on this repository to hear about the next one, then install it the same way, over the
  old copy.
- **Apple silicon only.** The app is built for Apple silicon. The small helper Claude Code runs is universal, so it
  also works when Claude Code runs under Rosetta.
- **Not yet verified:** Intel Macs (not supported), macOS 14 and 15 (built for 14, used daily on newer macOS), and a
  first launch on a clean user account. Reports from those setups are especially welcome.
- **Upstream formats can change.** Claude Code's status line is documented, but Codex's session files are not. If an
  agent changes what it writes, Clepso shows its numbers as missing or stale, never as 0%. A fix will follow as a
  patch release.

### Known limitations

- **Limits come from Claude Code's status line, which runs in a terminal** (including an IDE's built-in terminal, such
  as VS Code's or JetBrains'). The **Claude desktop app's Code tab** and the **VS Code graphical panel** don't run the
  status line. Usage there still counts against your plan (and, with agents per task on, the desktop app's tasks are
  counted), but the limit figures update only when a terminal session next reports.
- Claude Code's status line reports the 5-hour and 7-day limits only. Others, such as a weekly limit for one model,
  appear in `/usage` in Claude Code.
- Clepso reads Claude Code and Codex. Other agents (Gemini CLI, Cursor, GitHub Copilot, Windsurf, Grok) are planned,
  not built.
- Cost figures are Claude Code's own estimate at list price, not your bill.

### Uninstall cleanly

1. In Clepso, open **Settings** (⌘,). Under **Your data**, choose **Delete…**, keep everything ticked, and confirm
   with **Delete All**. This removes Clepso's database, diagnostics log and notifications, switches off Open at login,
   and takes Clepso out of Claude Code, restoring your settings from the backup. Tick "Also delete settings backups" if
   you don't want to keep them.
   - To only disconnect from Claude Code and keep your history, use **Remove from Claude Code…** in Settings instead.
2. Quit Clepso (Quit in the panel) and drag **Clepso** from Applications to the Trash.

If the app is already gone, your Claude Code status line keeps working: Clepso's wrapper falls back to your original
command when the app is missing.

### Checksums and signature

`SHA256SUMS` lists the disk image's SHA-256. The app and the disk image are signed with
"Developer ID Application: Obi Elvis (DD8UY75RZT)", use the hardened runtime, carry no sandbox or other exception
entitlements, and are notarised and stapled. To check: `spctl -a -vvv -t exec /Applications/Clepso.app` should print
`accepted` and `source=Notarized Developer ID`.
