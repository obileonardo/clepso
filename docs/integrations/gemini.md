# Gemini CLI recorded activity

Enable **Read recorded token activity** in Settings → Gemini CLI. This optional reader scans the newest 16 retained Gemini CLI recordings on this Mac and displays counters in Limits. The files also contain conversations: Clepso decodes only message identifiers (for deduplication), timestamps and numeric token fields, keeps numeric activity, hashed deduplication keys and a temporary file cache in memory, and discards transcript content, tool arguments, thoughts and raw message/session identifiers. File paths are used to find recordings and cache their modification times, and are never persisted or uploaded. It does not read OAuth/configuration files or turn on telemetry. No counts are uploaded or added to MCP/widget snapshots by this implementation.

Input includes cached input; cache is shown separately without adding it twice. Output, reasoning, tool and the provider-reported total stay separate. Repeated message updates/checkpoints count once. Rewinds do not refund already-consumed tokens while those records remain in the file. Deleted/rewritten history can reduce the available evidence. This is retained recording activity, **not a billing ledger or subscription quota**. Percentage allowance/reset times remain unknown from this source. The Mac does not install or sign in to Gemini CLI for you.

Fixed roots: `~/.gemini/tmp` and Gemini's macOS sandbox runtime `~/.cache/.gemini/tmp`, project `chats` directories and one subagent level. Legacy JSON and current JSONL are supported; a migrated JSONL file supersedes the matching JSON. Reads are bounded to 8 MiB/file, 256 KiB/JSONL record and 8192 message counters/file. At most 4096 directory entries and 16 selected files are processed per scan. Oversized/unreadable/incomplete or additional coverage is labeled partial. Unchanged files use an in-memory cache; no paths are persisted. Symlink components below the trusted HOME, nonregular files and other owners are rejected with directory-relative no-follow reads. Polling runs off the main actor, consent/demo/deletion transitions discard in-flight results, and disabling clears the in-memory reader.

Schema and behavior verified against Google's [recording types](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/services/chatRecordingTypes.ts), [recording implementation](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/services/chatRecordingService.ts) and [storage layout](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/config/storage.ts), inspected 22 October 2026. Synthetic reader and app lifecycle checks are distinct from a real signed-in Gemini run, which remains unverified on this Mac.
