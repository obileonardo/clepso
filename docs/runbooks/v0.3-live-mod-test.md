# v0.3 live test: Clepso's Claude Code mod on the founder's Mac

What this is: the first install of `clepso-limits` into your real Claude Code, a check in the Claude desktop app's
Code tab, a 2-minute check in the VS Code panel, and the removal, with SHA-256 proof that `~/.claude/settings.json` is
back to its exact bytes. Design: `docs/specs/mod-bridge.md`. Nothing here runs until you give the go; every step that
writes says so.

- **Time:** about 25 minutes (VS Code part: 5 more, if you have VS Code with a current Claude Code extension).
- **What it touches:** `~/.claude/settings.json` (two entries added, then removed), `~/.claude/clepso/` (the mod's
  folder and one script, then removed), Clepso's own database (readings marked as from the mod). Claude Code's own
  plugin records under `~/.claude/plugins/` may keep a note of the `clepso` marketplace after removal (step U4).
- **What it costs:** two or three short Claude replies ("say hi"), on your plan, in sessions you start yourself.
- **What it never does:** read prompts, replies, files or credentials (the mod's calls are fixed:
  `claude plugin validate mod/claude-code/plugins/clepso-limits` lists them), or send anything off the Mac.
- **Abort at any point:** step R (restore), which puts back the exact bytes from your own copy.

Open questions this answers (spec §12): Q1 does `$.process.run` work in the Code tab, Q2 what `/plugin` shows after
removal, Q3 first session or next one, Q5 VS Code surfaces and status line, Q6 session id shared with hooks.

---

## 0. Before you start (read only)

```bash
claude --version                                   # 2.1.287 or later
cd "$(mktemp -d)" && claude plugin test; cd -      # expect: "no hooks module to load" (mods can load here)
df -h /                                            # keep at least 8 GB free for the build
```

In the Claude desktop app, open a local session in the **Code** tab, enter `/status` and note the **Claude Code** row
(2.1.286 or later; 2.1.299 on 19 Oct). Close that session.

Keep your own copy of the settings file and its fingerprint, outside `~/.claude`:

```bash
mkdir -p ~/Desktop/clepso-v03-test
cp -p ~/.claude/settings.json ~/Desktop/clepso-v03-test/settings.before.json
shasum -a 256 ~/.claude/settings.json | tee ~/Desktop/clepso-v03-test/settings.before.sha256
claude plugin list --json > ~/Desktop/clepso-v03-test/plugins.before.json
claude plugin marketplace list --json > ~/Desktop/clepso-v03-test/marketplaces.before.json
```

## 1. Build and run the v0.3 branch (writes: the build folder only)

```bash
cd ~/Developer/clepso-worktrees/v0.3 && git log --oneline -1 && make app
```

Quit the installed Clepso from its menu (**Quit Clepso**; not `pkill`). Then:

```bash
open ~/Developer/clepso-worktrees/v0.3/build/DerivedData/Build/Products/Debug/Clepso.app
```

This debug build uses your real data and `~/.claude`. At launch it re-points the status line's and hooks' scripts at
its own helper (Repair, no `settings.json` change); the installed app re-points them back when you reopen it (step U5).
There is no database migration on this branch, so going back is safe.

## 2. Install (writes: settings.json, ~/.claude/clepso/)

1. Dashboard › **Settings** › Claude Code › **Desktop app and VS Code panel**: turn it on.
2. Read the consent sheet. It names the file and shows the two entries. Click **Add the mod**.
3. Expect: "Mod added. Limits from the desktop app and VS Code arrive from your next Claude session there." The row
   says "On · nothing from the desktop app or VS Code yet…".
4. Check what changed (only added lines, the two entries):

```bash
diff ~/Desktop/clepso-v03-test/settings.before.json ~/.claude/settings.json
ls -la ~/.claude/clepso/claude-mod/plugins/clepso-limits/hooks ~/.claude/clepso/mod-handoff.sh
diff -r ~/Developer/clepso-worktrees/v0.3/mod/claude-code ~/.claude/clepso/claude-mod && echo "mod copy identical to source"
```

## 3. Desktop app, Code tab (the main check)

| Step | Do | Pass when |
|---|---|---|
| D1 | Quit the Claude desktop app fully (⌘Q) and reopen it, so it reads the new settings. Code tab → new **local** session. **+ › Plugins › Manage plugins** | `clepso-limits` is listed and on. (If not: note it, go on to D2; Claude Code may register the marketplace in the background, spec R4) |
| D2 | Send `say hi` and wait for the reply. Send a second short message. | Replies as normal, no error or new line from the mod |
| D3 | Within 2 minutes look at Clepso: Settings row, menu bar | Row reads "On · last reading from the desktop app or VS Code just now"; the menu bar's 5-hour number matches the desktop app's usage ring (± 1 point) |
| D4 | Run the query below | `mod_rows` ≥ 1 on the row whose `first_task` is your message (Q1, Q6) |
| D5 | Run `/model` in that desktop session, then `sqlite3 -readonly "$HOME/Library/Application Support/Clepso/clepso.sqlite" "select model_id, model_display_name from sessions order by last_seen_at desc limit 3;"` | The desktop session's `model_id` is the full id of the model `/model` names (for example `claude-opus-5-5`, with `[1m]` for that variant), the same string a terminal session on that model stores; `model_display_name` is empty for it (spec F11, Q4) |

If D3 shows nothing after a second message: start one **more** new session and send `say hi` again (Q3: the first
session may predate the background registration). Still nothing: note it for the report and go to U.

```bash
sqlite3 -readonly "$HOME/Library/Application Support/Clepso/clepso.sqlite" "
select a.session_ref,
       count(*) as tasks,
       datetime(min(a.started_at)/1000,'unixepoch','localtime') as first_task,
       (select count(*) from observations o join sessions s on s.id = o.session_id
         where s.provider_session_key = a.session_ref and o.metadata_json = '{\"channel\":\"mod\"}') as mod_rows,
       (select count(*) from observations o join sessions s on s.id = o.session_id
         where s.provider_session_key = a.session_ref and o.metadata_json is null) as status_line_rows
  from agent_tasks a
 where a.started_at > (strftime('%s','now') - 900) * 1000
 group by a.session_ref;"
sqlite3 -readonly "$HOME/Library/Application Support/Clepso/clepso.sqlite" "
select datetime(max(received_at)/1000,'unixepoch','localtime') as last_mod_reading, count(*) as mod_rows
  from observations where metadata_json = '{\"channel\":\"mod\"}';"
```

`mod_rows` ≥ 1 and `status_line_rows` = 0 on the desktop session: the mod reported it and the session id is the
hooks' too (Q6). `mod_rows` only in the second query (none per session): the ids differ (Q6 = no), which is safe but
means desktop sessions get two rows; note it.

## 5. VS Code panel, 2 minutes (only with VS Code or Cursor and the Claude Code extension **2.1.299 or later**)

Your Cursor has 2.1.92, which is too old for mods: update the extension first, or skip this part and say so.
Check that **Use Terminal** (`claudeCode.useTerminal`) is off, so you are in the graphical panel.

| Step | Do | Pass when |
|---|---|---|
| V1 | Open the Claude Code panel, type `/plugins` | `clepso-limits` is listed and on |
| V2 | New conversation, send `say hi`, wait for the reply | Normal reply |
| V3 | Within 2 minutes run the first query again | That session has `mod_rows` ≥ 1. `status_line_rows` ≥ 1 too means the panel also runs the status line (Q5): fine, the status line then holds the window (spec §7) |

## U. Remove (writes: settings.json, ~/.claude/clepso/)

1. **U1.** Settings › Claude Code › **Desktop app and VS Code panel**: turn it off. Expect "Mod removed. Claude Code's
   settings are byte-for-byte as before." ("Your other changes … were kept" means something else edited the file in
   between, for example `/config` or Claude Code itself; then U2 fails by design and U2b explains the difference.)
2. **U2.** Verify the exact bytes:

```bash
shasum -a 256 -c ~/Desktop/clepso-v03-test/settings.before.sha256        # expect: settings.json: OK
```

   **U2b**, only if U2 failed: `diff ~/Desktop/clepso-v03-test/settings.before.json ~/.claude/settings.json` must show
   only changes that are not Clepso's (no `clepso` line).
3. **U3.** `ls ~/.claude/clepso/` lists no `claude-mod` and no `mod-handoff.sh`.
4. **U4 (Q2).** Quit and reopen the desktop app, Code tab, **+ › Plugins**. Note whether a `clepso` marketplace or an
   error appears. Also run (read only):

```bash
claude plugin list --json | diff ~/Desktop/clepso-v03-test/plugins.before.json - ; \
claude plugin marketplace list --json | diff ~/Desktop/clepso-v03-test/marketplaces.before.json -
```

   A leftover `clepso` entry here is Claude Code's own record (spec R6); the plugin is no longer enabled. Leave it for
   the report. `claude plugin marketplace remove clepso` would clear it, but it re-writes the whole `settings.json` in
   Claude Code's own formatting (spec E-A), so don't run it during the test.
5. **U5.** Quit the branch build from its menu; reopen your installed Clepso. Then:

```bash
grep CLEPSO_SHIM ~/.claude/clepso/statusline.sh ~/.claude/clepso/hook.sh    # both name the installed app again
```

## R. Restore (only if something went wrong)

Quit both Clepso builds from their menus, then:

```bash
cp -p ~/Desktop/clepso-v03-test/settings.before.json ~/.claude/settings.json
shasum -a 256 -c ~/Desktop/clepso-v03-test/settings.before.sha256         # expect: OK
rm -rf ~/.claude/clepso/claude-mod ~/.claude/clepso/mod-handoff.sh ~/.claude/clepso/mod-state.json
```

Reopen the installed Clepso. Keep `~/Desktop/clepso-v03-test/` until the report is written, then delete it (it holds
a copy of your settings).
