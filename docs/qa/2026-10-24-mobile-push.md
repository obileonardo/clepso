The first full gate run found an ignored local Supabase runtime secret in its overly broad scanner. The scanner previously echoed matching lines. Captured local output was redacted, the scanner corrected, and the full17 gates rerun successfully. No production secret was committed or published.

Production dry run selected exactly the two mobile migrations. Existing production advisor warnings concern the pre-existing profile trigger/account-deletion definers and password protection; they are not evidence of mobile delivery. Both migrations are deployed, mobile-signal is ACTIVE version1 with JWT verification enabled, and a subsequent migration dry run is up to date. Live synthetic-account checks verified both environment signers, owner isolation, registration/off/replay and a zero-destination signal; fixtures were removed and no email or Apple push was sent. The production advisor warnings are unchanged. Apple acceptance, opt-in physical phone/paired Watch behavior and public TestFlight distribution remain pending. A configuration/readiness success alone must not be reported as a delivered notification.

Reproducible runners: `scripts/test-mobile.py`, `backend/tests/mobile_{relay_http,relay_concurrency,signal_http}.py`, the pgTAP files and `node --test backend/supabase/functions/mobile-signal/handler.test.ts`. Local API runners hard-check the synthetic project's localhost port. Hosted CI compiles phone/Watch and runs actual iPhone lifecycle tests without credentials.

Production phone/embedded Watch export build3 passed strict code-signature verification. The exported app's push entitlement and Info setting both use Production; reviewed privacy manifests are present in both bundles. The app uses Apple's HTTPS/Keychain facilities and SHA-256, without proprietary encryption. The explicit non-exempt-encryption value follows [Apple's built-in encryption guidance](https://developer.apple.com/documentation/security/complying-with-encryption-export-regulations). Phone UserDefaults access is limited to app-owned preferences and declares [CA92.1](https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacyaccessedapitypes/nsprivacyaccessedapitype). Optional linked email/account/installation/usage data is declared for app functionality, with tracking false; the Watch has no direct network collection. [Apple privacy collection reference](https://developer.apple.com/documentation/technotes/tn3184-adding-data-collection-details-to-your-privacy-manifest). Export receipt is [mobile-export.json](2026-10-24-mobile-export.json). Export success is not upload, processing, review or TestFlight availability.

The first hosted native run rejected the hardcoded iPhone17Pro/iOS27.1 combination. The runner now filters runtime-supported device types, architectures and OS ranges; three regression fixtures pass, and the five actual native lifecycle tests passed again. Both source icons were flattened onto the existing dark theme as opaque RGB with the owner's explicit Python approval; every original fully opaque artwork pixel was preserved. A binary PNG preflight now rejects alpha/transparency before simulator and distribution builds. Apple rejected build3's alpha-bearing Watch icon; corrected build5 export/upload validation continues.

Development build4 was successfully installed over the owner's unlocked USB-connected physical iPhone after wireless tunnel failures. The signed profile, explicit bundle ID, Development entitlement/Info agreement and build were checked before installation. This update did not launch the app, sign in, enable sharing or request notification permissions; physical Watch behavior and delivery remain unverified.
